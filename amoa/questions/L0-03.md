# L0-03 — monorepo React Native

**Statut retenu : partielle.** Six des sept critères d'acceptation sont vérifiés contre les
outils réels (voir le message du commit `L0-03-react-native-monorepo`). Le septième (build
Android en mode release) n'a pas pu être tenté du tout, pour une raison d'environnement, pas de
conception.

## Écart — critère d'acceptation 4 non vérifiable sur cette machine

**Ce que demande la spécification.** « Le build Android en mode release produit un APK pour
chaque app. »

**Pourquoi cela pose problème.** Cette machine n'a aucun SDK Android installé : ni
`ANDROID_HOME`, ni `ANDROID_SDK_ROOT`, ni `~/Library/Android/sdk`. `./gradlew assembleRelease`
échouerait immédiatement à la résolution des outils de build Android, avant même de compiler quoi
que ce soit. Ce n'est pas un défaut du monorepo : les deux projets natifs `apps/client/android`
et `apps/driver/android` existent, sont structurellement corrects (générés par
`@react-native-community/cli`, avec espace de noms, Gradle wrapper et `debug.keystore` corrects
pour chaque app), et n'ont simplement pas pu être compilés faute d'outillage disponible.

**Second constat, lié.** `react-native@0.86.2` exige Node `>= 22.11.0` (`package.json`
`engines`). Cette machine a Node `20.15.1`. `npm install` a réussi avec des avertissements
`EBADENGINE`, et tout ce qui a pu être vérifié ce soir (Metro, `tsc`, `jest`, `eslint`) a
fonctionné malgré l'avertissement -- mais rien ne garantit que ce sera encore vrai pour des
opérations plus profondes (build natif, justement), ni pour de futures versions de dépendances
qui pourraient être moins tolérantes.

**Options considérées.**

1. **Retenue.** Documenter l'écart, livrer tout ce qui est vérifiable ce soir, marquer la tâche
   « partielle » plutôt que « finie » dans `amoa/rapport-nuit.md`. Le protocole de la nuit
   demande d'appliquer une hypothèse explicite et d'avancer quand c'est possible -- ici il n'y a
   pas d'hypothèse à appliquer, seulement un outil manquant à signaler.
2ᵉ option écartée : tenter d'installer un SDK Android headless cette nuit pour lever le blocage.
   Rejetée : une installation de SDK Android (plusieurs Go, licences à accepter, configuration
   d'émulateur) dépasse largement le périmètre d'une tâche de squelette, et le risque de casser
   autre chose en cours de route sur une session non surveillée est réel.

**Recommandation.** Avant de reprendre ce lot : mettre à niveau Node sur les machines de
développement et d'intégration continue vers `>= 22.11.0` (L0-05 en dépend directement --
critère « build Android en mode release » de sa propre chaîne), et installer un SDK Android
(ligne de commande suffit, pas besoin d'Android Studio complet) pour permettre à quelqu'un de
vérifier réellement le critère 4 avant de considérer L0-03 terminée.

## Urgence

**Bloquant** pour la validation complète de L0-03 et pour tout critère d'acceptation ultérieur
qui suppose un APK installable (démonstration, tests sur appareil réel). Non bloquant pour la
suite du travail de ce soir : le reste du monorepo (paquets partagés, Metro, TypeScript, lint)
fonctionne et peut servir de base aux tâches suivantes sans attendre la résolution de ce point.
