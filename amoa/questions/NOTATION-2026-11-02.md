# Notation réciproque client ↔ chauffeur (2 novembre)

Demande du jour : à la fin de chaque course, le client et le chauffeur se notent l'un l'autre ;
chacun voit sa note sur cinq étoiles dans son profil ; le client ne peut pas modifier sa note
ensuite ; le chauffeur, lui, peut corriger la sienne depuis son historique.

L4-09 ne prévoyait que le premier sens (le client note le chauffeur). Ce qui suit est donc une
extension, avec ses écarts.

## Livré

| | Client → chauffeur | Chauffeur → client (nouveau) |
|---|---|---|
| Où | résumé de fin de course (inchangé) | écran d'encaissement : « Notez votre client », un appui par étoile |
| Quand | course `settled` (inchangé) | course `completed` ou `settled` — la note ne dépend pas de l'encaissement, resté en file hors connexion |
| Correction | **jamais** (`RATING_ALREADY_SUBMITTED`, inchangé) | **oui**, depuis « Mes courses » : la nouvelle note remplace l'ancienne (une ligne par course) |
| Hors connexion | file + rejeu (inchangé) | file + rejeu, même runner que l'encaissement |
| Moyenne affichée | profil du chauffeur | profil du client |

Les deux profils affichent « ★ 4,7 · 12 avis », « Nouveau · 2 avis » sous le seuil
`babana.rating_min_count` (même règle L4-09 pour les deux sens), « Pas encore d'avis » à zéro. Le
profil relit `GET /me` à l'ouverture : la note de la session date du démarrage.

**Nouveau : « Mes courses » côté chauffeur** (profil → Mes courses) — ses courses terminées,
paginées comme celles du client, avec la note donnée et les étoiles pour la poser ou la corriger.
Une course annulée n'a pas d'étoiles ; c'est le serveur qui le dit (`clientRatingAllowed`).

Vérifié de bout en bout sur les émulateurs (course C2026002608) : note 4 posée avant
l'encaissement, client 5 étoiles au chauffeur, correction 4 → 2 depuis l'historique (même ligne
réécrite), deux autres courses notées → « ★ 3,7 · 3 avis » sur le profil de Nadège.

**Contrat C-01, additif** : `rating` dans l'objet utilisateur (`GET /me` et sessions),
`POST /rides/{id}/client-rating` (`rateClient`), `GET /drivers/me/rides` (`driverRideHistory`).
Modèle `babana.client.rating`, en lecture seule au back-office : « Flotte › Avis sur les clients »
(l'ancien menu « Avis » devient « Avis sur les chauffeurs »). Aucun accès ORM pour les apps, comme
`babana.rating`.

## Écarts et choix à confirmer

**1. Pas de nom du client dans l'historique du chauffeur.** La règle L8-01 ne laisse le chauffeur
lire la fiche de son client que pendant la course. L'historique montre la date, le trajet, le
montant et la note — assez pour reconnaître une course, sans rouvrir l'identité du client après
coup.

**2. Le chauffeur corrige sans limite de temps.** La demande ne fixe pas de délai. Une note
corrigée trois mois plus tard reste possible ; si l'on veut une fenêtre (48 h, par exemple), c'est
un paramètre en base à ajouter. Pour le client, L4-09 parlait de « non modifiable après un court
délai » : c'est désormais « jamais », comme demandé.

**3. Noter n'est pas obligatoire, ni d'un côté ni de l'autre.** « Terminé » reste accessible sans
note : un chauffeur ne doit pas être retenu à l'arrêt avant sa course suivante. La course non
notée reste notable plus tard depuis « Mes courses ».

**4. Écart déjà relevé, plus visible maintenant** (DEMO-2026-10-30.md) : le client ne peut noter
qu'une course `settled`, alors que le chauffeur peut noter dès `completed`. Si le client note
avant que le chauffeur ait confirmé l'encaissement, il lit « Vous pourrez noter la course dès que
le chauffeur aura confirmé le paiement ». L'option B de cette note (noter dès `completed`)
alignerait les deux sens.

Je propose D-suivant : notation réciproque — le chauffeur note son client dès la fin du trajet et
peut corriger sa note (délai à fixer ou non) ; la note du client sur le chauffeur reste
définitive ; les deux moyennes sont servies par `GET /me` avec le seuil « nouveau » commun.

## Prolongements possibles, non faits

- **Montrer la note du client au chauffeur sur la proposition**, comme les grandes apps. C'est ce
  qui donne son sens à la notation des clients ; à décider, car cela peut faire refuser des
  clients mal notés.
- **Note très basse → alerte superviseur** (un 1 ou un 2 mérite un regard humain) : le filtre
  « Notes de 1 ou 2 » existe au back-office, sans alerte.
